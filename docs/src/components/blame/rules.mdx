## What it attributes

`task blame <task-key>` attributes the current title, column, priority, deadline, label membership, parent, relations and description lines to recorded activity. It reads active and archived tasks. A [reused key](/docs/data#task-key-reuse) selects its current task lifetime. Unknown and deleted keys produce the ordinary missing-task error.

## Field and membership attribution

Creation records can supply the initial attribution, including unset values. Later edits, moves and membership changes replace it. Labels are one collection, attributed to the latest attachment or removal, including removal when a label is deleted, when the recorded creation and changes add up to the current number of labels. Column and label renames preserve membership attribution while returning the current names. Parent assignment and removal follow outgoing `subtask` relation events. Each current relation carries its own creation attribution, including incoming links and the parent link.

## Description lines

Description comparison matches whole lines exactly, including whitespace. Unchanged lines carry their attribution, inserted or replaced lines belong to the introducing edit, and deleted lines disappear. Blank lines are preserved. A terminal newline ends the preceding line without adding another line, and changing only that newline preserves attribution. Null and empty descriptions have no lines. Matching keeps the shared lines at the start and the end in place, then matches the longest sequence of remaining lines that both versions share in the same order. When a comparison could be read more than one way, it treats a line as removed before treating it as added. Each edit has a fixed search budget, enough for about 2,500 replaced lines. Past it, lines not yet matched belong to that edit, so a heavily reordered description reads as rewritten.

## Unrecorded attribution

Attribution is `null` when the required history is absent or unrecognized. Text calls it `unrecorded`. A scalar's latest recorded new value must agree with its current value. Description edits must join the previous recorded version before they can carry its attribution. A gap starts with unattributed old lines and attributes only inserted lines to the next edit. A later description record without both the old and new text discards the carried line attribution, so later edits cannot inherit it. If the final recorded description differs from the current text, all current lines are unattributed.

## Recorded identity and JSON

Recorded events retain the stored actor name, kind and identity fields, with `null` for absent metadata. Missing actor identity is separate from missing event attribution. Event IDs open with `zinn activity view <activity-id>`. Blame reads task content and history without recording activity.

With `--json`, the command returns the [`TaskBlame` result](/docs/core/blame#result-types).
