### Added

- `task claim <task-key> --lease <duration>` marks a task as being worked on by you for `1m` through `24h`. `task next` skips live claims, `task heartbeat` renews one, and `task release` removes it. A claim expires with its lease or 24 hours after your last change to the task, and `--force` takes over a live claim. Task objects gain a `claim` field. See [CLI](/docs/cli/next#claim-tasks) and [Core](/docs/core/writing#task-claims).
  - **Schema version 6:** the claim table is new. A published release upgrades an existing database on first use after saving a backup, and `zinn migrate` runs the upgrade on request. An older Zinn can read the upgraded database but refuses changes to it.
- `task next` shows the next ready task: active, in a todo or backlog column, with every dependency archived or in a done or cancelled column. Todo tasks come first, then priority, earliest deadline and oldest task. `--column` narrows the choice, and `--json` prints `null` when nothing is ready. See [CLI](/docs/cli/next#next-ready-task).
- Edit commands take `--expect-*` flags for the values read before the edit, and core's edit methods take the same check as `expected`. A differing value fails with `conflict` and names the changed fields, so one of several concurrent editors succeeds. See [CLI](/docs/cli/editing#edit-tasks).
- `task move --from <column>` moves a task only if it is still in that column, otherwise it fails with `conflict` and the expected and actual columns. Core's `task.move` and `task.moveMany` take `fromColumn`. See [CLI](/docs/cli/editing#move-and-order-tasks).
- `task list --state` takes `open`, `closed` or `all` and filters by column category. `all` is the default. Core's `task.getAll` and `task.getPage` take `state`. See [CLI](/docs/cli).
- `activity list --follow` prints activity as clients commit it until stopped, and with `--json` prints one record per line. It cannot be combined with `--limit` or `--starting-after`. Core adds `activity.follow`. See [CLI](/docs/cli/activity).
- `zinn doctor` checks settings, the store, database, search index and installed skill, suggests a fix for each problem, and changes nothing. It exits 1 on warnings or problems. See [CLI](/docs/cli/help#check-for-problems).
- `zinn skill install` installs the bundled agent skill for every agent through the skills CLI. The installed skill matches the CLI version, so rerun it after upgrading. See [CLI](/docs/cli/help#agent-skill).
- The `busyTimeoutMs` setting sets how long a command waits for another Zinn process before failing as busy. It defaults to `30000`, and `0` fails at once. See [Settings](/docs/settings#wait-for-a-busy-database).
- `update` is an alias for `edit` in every command that has one. See [CLI](/docs/cli/help#command-aliases).

### Changed

- **Breaking CLI and core API:** every column has a category: `backlog`, `todo`, `in_progress`, `review`, `done` or `cancelled`. Tasks in `done` and `cancelled` columns are closed, and column names are colored by category. `project column create` requires `--category`, and core's `column.create` requires `category`: add it to scripts that create columns. `project column edit` and `column.edit` take `--category` or `category`, ask for confirmation when the column holds tasks, and `--json` column results add `category` while task results add `column_category`. The upgrade gives Backlog, TODO, In Progress, Doing, Review, Done and Cancelled the matching category, and every other column `todo`. See [CLI](/docs/cli/projects#start-a-project).
- A process that keeps the database open refuses its next change after another process changes the schema version, and reads keep working until it restarts. Core throws a `CoreError` with kind `conflict`. See [Core](/docs/core/storage#database-compatibility).

### Removed

- **Breaking CLI and core API:** `--allow-legacy-read` is removed, and core's `configureDatabase` no longer takes `allowsLegacyRead` or `onLegacyRead`. Remove the flag from scripts and the options from core calls. A database without a schema version is refused, while a database from a released version stays readable. See [Data](/docs/data#upgrade-a-database).

### Fixed

- A failed `ROLLBACK` now makes the connection refuse every later statement until it closes, instead of allowing a write that could be lost. The rollback error stays attached to the original error.
- `zinn restore` rechecks the backup after taking the write lock, so a backup deleted or replaced in between is refused and the database is left as it was. It also refuses a backup path that leads to the database itself. See [Data](/docs/data#restore-a-database).
